netkeep no longer claims the old `browser-local.lock` alongside the local account's own browser lock. Only code from before P2-10 (2026-09-23) held that file alone, and none of it can share a lock directory with netkeep since the rename. Every browser path still takes its account's `browser-account-<id>.lock`, so two runs on one account still never attach at once. `netkeep preflight` now builds its browser provider the same way every other command does.
