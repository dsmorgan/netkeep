One browser client per LinkedIn account, across processes. The activity lock used to live in one process's memory, so `netkeep preflight`, `netkeep posture --probe` or `netkeep rehearse` in a terminal opened a second CDP client while `netkeep serve` held the browser. Every browser path now takes an OS file lock under the data directory (`locks/browser-<account>.lock`) before it attaches, and a command that finds it held answers busy, naming the process that holds it, instead of attaching. A holder that crashes releases the lock with its process. `netkeep posture` reports whether the lock is held and by what.
