`POST /api/v1/linkedin/browser/check` starts a Check connection run: it attaches to netkeeper's Chrome, reads the LinkedIn session from the cookie jar the way `netkeeper preflight` does, and detaches. It visits no page and spends no budget. The result shows on the run and in `GET /api/v1/linkedin/browser/health`. It answers `409` while another run or process holds the browser. There's no button for it yet (#605 decides where it goes).
