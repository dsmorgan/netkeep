`netkeep update` can now roll back across versions that add to its state file: a version reads a `state.json` with fields it doesn't know, keeps them and writes them back, instead of refusing the rollback. The existing fields and phases are frozen and pinned by a test; a phase a version doesn't know is still refused, and a rollback still never restores once any scheduler may have run. Each version's downloaded constraints file, which the rollback reinstalls from, is now written atomically and durably (`netkeep.fsutil.write_atomic`), as the state file and scheduler marker already were.
