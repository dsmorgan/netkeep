`netkeep open` now opens the UI as an app window in netkeep's own Chrome, its dedicated profile on the configured debugging port, and starts that Chrome when it isn't running. When the Chrome is running, the window opens there. It refuses, and says why, when the port answers as another Chrome, when that profile is open without the port, or, for a cold start, while a run holds the browser. It still prints a one-time link for another browser, and `--link-only` prints only the link. `POST /api/v1/linkedin/browser/start` does the same from the UI, for the coming **Start Chrome** button. This is the one process netkeep starts (ADR 0012).
