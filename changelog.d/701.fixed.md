netkeep now refuses to start when `config.toml` has a `linkedin.timezone` it doesn't know or a `linkedin.cdp_url` with no host, no valid port, or a form that doesn't parse. The error names the key. Before, a typo such as `America/New York` caused a 500 on run starts and a misleading 404 on prefill and check-sent, and a malformed `cdp_url` crashed `GET /linkedin/browser` and `netkeep browser launch`. A run gate given an unknown time zone now refuses the run with a clear message. When `cdp_url` names no port, `netkeep browser launch` and the LinkedIn page show no Chrome command, instead of one on port 9222 that netkeep would never attach to.
