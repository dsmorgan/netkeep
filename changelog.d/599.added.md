**Start Chrome** on the dashboard and the LinkedIn page's **Browser** card starts netkeep's own Chrome, with netkeep in its own window, or opens netkeep in it when it's running, and says how it went in plain words, refusals included. The card, and the posture report's dedicated-profile row (with or without `--no-probe`), show whether netkeep's Chrome is running, and the button is disabled while a run uses the browser or a start is under way. A new setting, **Start netkeep's Chrome when netkeep starts** (off by default, `linkedin.start_chrome_at_startup`), starts it once `netkeep serve` is listening, so with **Run at login** on, Chrome starts when you log in. It starts nothing when netkeep's Chrome is already running or a run holds the browser. Both use the one launcher, which never touches a Chrome on another profile. You still sign in to LinkedIn yourself.
