`scripts/reset-data.sh --restore` now hands the restore to the checkout's own `netkeep restore` (`.venv/bin/netkeep`, never one found on PATH), so it holds the serve lock, refuses a database from a newer netkeep, turns Settings-page LinkedIn auto-send off, and runs `db upgrade`, as the CLI does. Afterward the script checks the restored database itself and stops loudly if the auto-send setting is still there. It used to copy the archive into place with `cp`, which brought auto-send back on with no confirmation. The script still archives the database in place first.
