`netkeep update` upgrades an installer or uv tool install in place. It checks the release's constraints file against its `SHA256SUMS`, refuses while you run `netkeep serve` yourself, stops the login item, backs up the database, installs the release with its pinned constraints, then hands over to the new version, which starts the login item and checks that `serve` answers with the new version. If the install or that check fails before the new version's scheduler started, it reinstalls the old version and restores the backup by itself; after the scheduler started, it stops and explains instead, because a restore could forget what was sent. `netkeep update --check` only reports a newer release. A checkout is refused: use `git pull` and `make install`. While an update is in progress, other commands refuse, except `serve`, the recovery commands (`restore`, `login-item`), `version`, `--help` and read-only status commands.
