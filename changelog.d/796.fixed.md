netkeep now reads every LinkedIn link and tab address the way Chrome does before it trusts one. Before the Contact info click and the Message click, it checks that the tab is on LinkedIn itself, not only at the profile's path. It refuses a link or address that Chrome and netkeep could read as two different hosts: one with a backslash, a user name before `@`, an encoded or empty host (`///in/…`, `///messaging/compose/…`), or a control character or space. That covers the Contact info and Message controls, the message bubble's header, the never-messaged card's links, where a profile, the connections list or the inbox landed, a profile's redirect, and the profile link in the contact-info overlay. Such a link used to pass some of these checks while Chrome would have opened another site.
