Enrichment now reads LinkedIn's missing-profile page as not found. A profile url that doesn't exist answers `200` with a page that has no top card, and the page then moves the tab to `/404/`. That visit used to count as unreadable, so two missing profiles in a row stopped the run and the contact was never marked gone. Now the visit is `NotFound`, spends no scroll, and adds to the contact's not-found streak. The tab's path must be exactly `/404/`, the document must name the missing page, and no profile screen or redirect may have been seen during the visit.

So that a page LinkedIn serves for every profile can't mark contacts gone, a run now stops as `many_not_found` after 4 profiles in a row are not found, or once more than half of 6 or more visits are not found. Two missing profiles in a row still don't stop a run. A not-found visit is saved as it happens, as an attempt. Its not-found streak is added only when the run stops, and only when the run reached its own end or a budget or active-hours limit. A run that stops as `many_not_found` (those visits are recorded as `not_found_discounted`), is cancelled, stops on LinkedIn's answer (a checkpoint, a throttle, a sign-out, a changed route, lost answers), or ends with an error adds no streak.
